# Branch Sweep

You are cleaning up branches whose work has already landed: delete the merged ones locally and on the remote, prune stale worktrees, and leave protected branches and anything unmerged untouched. This is destructive - branch deletion, remote deletion - so it runs behind a plan you approve before anything is deleted.

The non-obvious reason this skill exists: a branch's merged status comes from GitHub, not from git. When a repo squash-merges, the branch tip is never an ancestor of the default branch, so `git branch -d` refuses every one of them with "not fully merged." That refusal is expected, not a signal the branch is unmerged. Cross-reference the complete paginated GitHub API result to know what actually merged, then force-delete those specific branches.

## Hard rules

- Plan first, delete after approval. Produce the sweep plan - what would be deleted locally, what on the remote, which worktrees pruned - show it, and wait for a go-ahead. Default mode is plan-then-approve.
- Approval is bound to each full local or live-remote OID in the plan, never just a branch name. Delete a ref only with a compare-and-delete operation against that approved OID; tip drift is a reason to stop and re-plan, not to refresh the OID silently.
- Bind GitHub discovery and remote deletion to `origin`: require exactly one fetch URL and one push URL resolving to the same canonical GitHub host/owner/repository, call `gh api` with that concrete hostname and repository endpoint, and query the exact push URL that deletion will target. An ambiguous, unsupported, or divergent identity suppresses every candidate.
- A plan is usable only if every internal sort, lookup, filter, copy, move, pipeline, and render succeeds. Abort nonzero before printing candidate sections on any construction failure; never present partially filtered authorization.
- Deletion candidates require a confirmed default branch from live origin HEAD, the GitHub repository API, or an explicit validated `--default <branch>`. A stale local `origin/HEAD` or assumed `main` is orientation only and suppresses every candidate until the helper is rerun with a confirmed default.
- Never touch a protected branch: the repo default (main/master) and the develop/prod/release family. Never delete the current branch.
- Merged means merged on GitHub. A branch is sweepable only if its current local or live-remote tip exactly matches the head SHA of a repository-owned PR in the complete paginated API result. A reused or advanced branch name is unmerged work, even when an older PR with that name merged. Do not infer merged-status from `git branch --merged` when the repo squash- or rebase-merges - it misses everything.
- Local and remote are two deletions. Deleting the local branch does not delete `origin/<branch>`. Sweep both, and report them separately so neither is silently skipped.
- This is deletion, not history rewriting. Never push an updated tip, rebase, or amend. The required deletion-only `--force-with-lease=refs/heads/<branch>:<approved-remote-oid>` is a compare-and-delete guard, not permission to rewrite a ref. If the ask is to rewrite or squash commits, stop and point at git-history-surgery.
- An unmerged branch is deleted only if I name it explicitly and confirm. Then say plainly that it was not merged and the work is being discarded.

## What gets swept

- A local branch whose current tip matches a repository-owned merged PR head SHA (per the complete `gh api --paginate` result).
- A live remote branch `origin/<branch>` whose tip at the exact approved push destination independently matches a repository-owned merged PR head SHA.
- Only unlocked, proven-clean live worktrees that hold an otherwise eligible local deletion candidate, and only when every live worktree holding that same branch passes. Clean means a successful NUL-delimited porcelain-v2 status query reports no tracked modifications, untracked files, or ignored files, and no registered submodule surface exists. One failing sibling makes the whole branch ineligible and classifies every same-branch worktree as blocking rather than removable.
- Every prunable worktree registration, as one distinct repository-wide metadata-cleanup set annotated by whether it belongs to a local deletion candidate. A remote-only candidate never makes a same-named live local worktree removable or implies that its divergent local branch may be deleted.

Always excluded: the default branch, the current branch, and the protected family (main, master, develop, prod, production, staging, release/*, hotfix/*). When unsure whether a branch is protected, skip it and list it as skipped.

## Procedure

1. Orient without changing refs. Do not fetch or prune before approval. The plan helper reads the current/local refs, proves one `origin` fetch URL and one push URL resolve to the same canonical GitHub repository, then queries the exact push destination's live HEAD/heads with `git ls-remote`. The concrete GitHub repository API is the second authoritative default source. If default discovery is unavailable, a potentially stale local `origin/HEAD` or assumed `main` is displayed only for orientation and every candidate is suppressed. Confirm the repository's default independently, then rerun that package-local helper with `--default <branch>`; a value conflicting with an available authoritative default is rejected.
2. Build the plan. Run [this skill's `scripts/sweep-plan.sh` helper](scripts/sweep-plan.sh) with the target repository as the working directory. It makes direct, nonmutating `gh api --hostname <origin-host> repos/<origin-owner>/<origin-repo>/... --paginate` and exact-push-URL `git ls-remote` queries, matches repository-owned merged PR head names and SHAs against each current local and live-remote tip, and reports the bound repository identity, exact shell-escaped push target, separate candidates, reason-bearing skips, unlocked/proven-clean removable worktrees, blocking worktrees, one complete all-prunable registration set, retained live worktrees, and discovery completeness. Worktree discovery uses NUL-delimited porcelain so legal control bytes cannot split records; every displayed worktree path and porcelain-supplied free-text reason is one reversible shell-escaped token. For each live candidate-held worktree, run `git --no-optional-locks -C <path> status --porcelain=v2 -z --untracked-files=all --ignored=matching --ignore-submodules=none`; any output, query failure, lock, or registered submodule surface makes that worktree blocking, makes every same-branch sibling blocking, and removes the branch from local candidates. Render the removable set only after the complete inventory proves every live holder of each branch passes. If the overall worktree-list query fails, suppress every local candidate while leaving independently proven remote candidates visible. If complete GitHub discovery fails, discard partial API output and mark every remote merge status unconfirmed. The local-only best-effort fallback passes the full live push-destination default OID directly to `git branch --merged` only after proving that exact commit object is locally readable; an unbound identity, unavailable live OID, or stale/assumed default suppresses fallback candidates.
3. Show the plan and get approval. Present the bound host/owner/repository and exact shell-escaped push URL, then the to-delete set (local branch + full OID / remote branch + full OID / exact shell-escaped proven-clean worktree token) and skipped/blocking set with reasons. Approval applies only to that exact destination, those branch tips, and the worktrees explicitly listed as unlocked and proven clean. Wait, unless I told you up front not to confirm.
4. Revalidate and execute in dependency order. Re-run the nonmutating identity, exact-push-URL ref, complete NUL-delimited worktree inventory, and every same-branch cleanliness/submodule query immediately before deletion; any query error aborts all local worktree removal and local CAS. If the unique fetch/push URL set, canonical repository identity, approved tip, protection, current branch, worktree binding, sibling set, lock, or content status changed, stop and re-plan that item. First remove only approved worktrees whose entire same-branch set is still proven unlocked and clean with `git worktree remove <path>`; never use `--force`. A local branch's compare-and-delete is forbidden unless every approved removal for that branch succeeded and an immediate complete `git worktree list --porcelain -z` recheck shows no remaining binding. A tracked, untracked, ignored, submodule-bearing, locked, or failed worktree is a reasoned skip for that local branch and every same-branch sibling. Separately revalidate the complete all-prunable registration set; because `git worktree prune` is repository-wide, run it only when every record it would currently prune is present in and approved from that fresh complete set, otherwise stop and re-plan. Then compare-and-delete each eligible approved local ref with `git update-ref -d refs/heads/<branch> <approved-local-oid>`; never substitute unchecked `git branch -D`. Finally compare-and-delete each approved live-remote ref against the exact approved URL with `git push --force-with-lease="refs/heads/<branch>:<approved-remote-oid>" <approved-push-url> :refs/heads/<branch>`; the fully qualified deletion refspec prevents a same-name tag from changing the target. Never substitute a remote name, `--delete <branch>`, or an unchecked delete. A failed comparison is a reasoned skip and must not be retried with the new tip. Keep going only with independent branches or independently approved remote refs whose own prerequisites still hold.
5. Report. List what was deleted locally, what was deleted on the remote, worktrees removed, and everything skipped with a one-line reason.

## Modes

- Default - plan, show, wait, then delete.
- "just do it" / "don't confirm" - skip the approval gate but still print the full plan as you execute it, and still honor every protection.
- Dry-run - run step 2 and stop; show the plan, delete nothing.
- A named branch - if I point at a specific branch, sweep just that one (still local + remote), under the unmerged-branch rule above.

## Edge cases

- Detached HEAD - a successful empty current-branch query means there is no current branch to protect; confirm the intended default before sweeping. A failed current-branch query aborts the plan rather than masquerading as detached HEAD.
- Local candidate checked out in a worktree - after approval and immediate revalidation, remove it without force only if it remains unlocked, status-empty including ignored/untracked files, and free of registered submodule surfaces; then delete the local branch. A blocking worktree blocks local CAS. A live worktree on a divergent local branch is retained even when a same-named live-remote tip is independently sweepable; if its directory disappears, its registration moves only to the all-prunable metadata set and still does not authorize branch deletion.
- Ignored files and submodules - ordinary `git worktree remove` can delete ignored-only data, so ignored status is blocking. Top-level status cannot prove recursively ignored submodule contents; conservatively retain any candidate worktree with a registered gitlink rather than attempting recursive authorization.
- Concurrent local checkout/worktree/content changes - Git can atomically compare-and-delete a ref OID, but it cannot couple that update to the separate current-branch, worktree-occupancy, lock, and content-status checks. Repeat every check immediately before removal/deletion and require a quiescent repository when another process could change any of them in that narrow interval; never force removal or trade the OID comparison for unchecked `git branch -D`.
- No GitHub-bound origin / no `gh` - an unprovable origin identity suppresses every candidate. For a proven GitHub-bound origin, discard any partial API result and do not guess at remote merges; local-only ancestry fallback is allowed only with the exact, locally readable live push-destination default OID. Stale/assumed orientation suppresses all candidates. Report each discovery boundary as incomplete.
- A protected pattern that is really a feature branch (e.g. `release/spike`) - when in doubt, skip and list it; let me override.
