# Image-First UI Workflow

For a new page, screen, or material visual redesign, create or accept a concrete UI reference before coding. A generated image is a target for implementation, not a loose moodboard.

For an existing interface, inspect and capture the current runnable/source-backed UI, design system, or authoritative Figma source first. It is already a valid target, even when discovered during the task. Preserve its literal content and behavior unless the user requested changes; an old screenshot folder is not proof of current state.

1. Define the target surface, platform, audience, and visual direction.
2. Use the authoritative existing or supplied reference. For new visual direction without one, generate a reference with the host-supported image tool when useful and permitted; do not make generation a prerequisite for a source-parity fix.
3. Record the reference's composition, alignments, spacing, type hierarchy, colors, component geometry, asset positions, and layering.
4. Use real image assets for illustrated, photographic, rendered, or textured material. Do not approximate those assets with decorative CSS.
5. Implement one screen or section at a time.
6. Capture the result at the same viewport and compare it to the reference.
7. Name the largest mismatches, correct them, and repeat until the main visual relationships agree.

Preserve exact source text when it exists. If a generated concept has unreadable text and no authoritative copy exists, use clearly identified draft copy consistent with its hierarchy and density; do not pass invented text off as source content.
